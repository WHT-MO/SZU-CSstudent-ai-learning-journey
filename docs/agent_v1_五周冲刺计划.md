## 0. 一句话目标（2026-09-23 学员更正）

> **这个项目的目的是两个：① 学习、理解新技术，提高能力和基础；② 作为简历，为实习创造优势。**
> **它不是为了让学员有个工具能用，而是为了理解并掌握 agent 开发。**

→ **目标函数因此改写**（这是本次最重要的更正）：

| | 旧口径（已作废） | **新口径** |
|---|---|---|
| 优化对象 | 工具的**可用性与鲁棒性** | **理解深度 + 可展示的证据** |
| 代码行数 | 1200–1800 行是目标 | 行数只是**副产品**，不是指标 |
| 验收 | "连续 5 天没有一天因为它出错而改回手做" | **每个模块你能讲出"为什么必须有它、没有它会怎样"**，且有自己的证据 |
| 砍功能的理由 | "功能少 = 你敢用" | "这个功能**教不到东西**，才砍" |

**"天天用"降级为加分项，不再是验收线**：仍然要能跑通、要真的用它干过活（不然是空的），
但**不追求"每天都靠得住"**——那会吃掉大量时间在边缘 case 上，而那些 case 教不到 agent 原理。

### v1 的验收标准（三条，缺一不可）

1. **结构能画**：不看资料，凭记忆画出 agent 的数据流与模块结构（你有这个强项——L17 复习课第一版就画到六到七成）。
2. **机制能讲**：每个模块用"12 岁能听懂"的话讲一遍，并指出**它解决什么、不解决什么**。
3. **坑能复现**：能**主动造出**下面这些故障并解释你怎么发现的、怎么修的（**每条的造法与前置条件见 §5.4，不许等它自然发生**）：
   - 工具调用死循环（用 `maxTurns` / `maxUnboundToolCalls` 兜住）
   - `reasoning_content` 漏传 → 400（**前置：必须开 thinking**）
   - 后台 asyncio 任务静默消失（Python 3.12 弱引用 → 主动 `gc.collect()` 触发）
   - 429 与指数退避（**用假 429 响应，不等真实限流**；含"哪些错误**不该**重试"）
   - 上下文被压缩前后，**发给模型的 messages 真的变小了**（不是只追加了一条记录）

> **判据一句话：能不能拿它去面试讲 20 分钟，且面试官追问"为什么这么设计"你能答。**

## 4. 五条纪律

1. **v1 跑通之前，不许读 Pi / dsh 的源码**（读结构分析可以，见 §9）。**Why（新口径）：** 你的目标是"理解并掌握"，而
   **抄一遍源码 = 能力错觉的最高级形式**——代码跑起来了，但每一行为什么这么写你都说不出。
   跑通之后再对照读，那时读的是"我当时为什么没想到"，学习效率最高。
2. **推理强度默认 `off`**（`thinking:{"type":"disabled"}`），需要时开 `low`。默认 `high` 会让每次工具调用前产生推理 token，而它**按输出价计费**。
   **例外（2026-09-23 补）**：**故障复现必须开 thinking**——`reasoning_content` 漏传那条 400 只在"开 thinking + 带 `tools`"时才会发生。
   → 做法：把 thinking 做成**参数**（`--thinking on/off`），日常迭代默认 `off` 省钱，**复现那一条时显式打开**。
3. **每格结束必须独立可验证**。不接受"这格写了一半"——写不完就当场缩小这一格的目标。
4. **每格先建 venv**：`python -m venv .venv` → 激活 → `python -m pip install httpx pydantic`。
   装完**必须** `Get-Command python` 确认指向 `.venv`（你已经栽过"改了东西 ≠ 它进了该去的地方"）。
5. **遇到报错，原样贴回**（连代码一起）——这是你已经定好的机制。
6. **【2026-09-23 学员否定旧纪律】不设"每格只能学一个新概念"这类额度。**
   **旧条作废**：那是我把学员 09-21 立的"教员一条消息只推一个概念"（约束的是**我的输出方式**）
   挪用成了"学员每格只能学一个新概念"（约束你的学习速度）——**这是两回事，后者会变成教员拖延的借口**。
   **改成**：**按应有流程接触新概念——哪个概念挡在交付物前面，就把它学到够用。**
   只保留一条兜底（**不是额度**）：**同一个点卡超过 20 分钟**，先写一句"卡在第几步、试过什么"再继续。
   **Why:** 五周冲刺的目标函数是理解 + 交付，人为限速直接损害它。
   **How to apply:** 每格开头可以直接认领"这格要碰 N 个新概念"；教员不得以"额度"为由推迟或简化。

## 5. 四个必须提前知道的坑 + 四类故障的"主动造法"

> **本节分工**：下面四个坑是**机制**（为什么会坏）；§5.4 是**造法**（怎么让它在我面前坏，而不是等它偶然坏）。
> **原则（2026-09-23 review 指出）：五条故障档案一条都不许靠"等它自然发生"**——那样五周内大概率一条都集不齐。

### 坑 1：`reasoning_content` 必须全程回传（**v1 最致命的一个**）

官方 Thinking Mode 文档原文：只要请求带 `tools` 参数，**所有历史轮次的 `reasoning_content` 都必须完整传回 API，否则直接返回 400**——即使某一轮模型没有调用工具也一样。

→ 影响：**W3 的会话存档如果不存 `reasoning_content`，会话第二次继续就永久 400**，而且报错信息不会告诉你原因。
→ 做法：存档时 assistant 消息必须同时写 `content` + `reasoning_content` + `tool_calls` 三个字段。
→ **前置条件：必须开 thinking**——详见 §5.4 第 1 条。默认 `off` 时永远复现不出来。

### 坑 2：Python 3.12 的 asyncio 任务**可能**被静默回收

Python 官方文档的措辞是**"可能"（may）**：事件循环对 `asyncio.create_task()` 创建的任务只持有弱引用，没有强引用的任务**可能**在 `await` I/O 时被垃圾回收，**不抛任何异常**——表现为"Agent 跑着跑着就不动了"。

→ 做法：维护一个全局任务注册表（`set()`），创建时 `add`，`done_callback` 里 `discard`；后台任务必须保留返回值并挂异常回调。
→ **不要靠"碰巧被回收"来验证**——用 `gc.collect()` 主动触发，见 §5.4 第 2 条。

### 坑 3：`emit()` 顺序必须在 W1 定死

**先归约内部 state（含 assistant message 的 `tool_calls` 提取），再按注册顺序 `await` listener。**

→ 如果顺序反了，listener 读到的是**更新前的 state**；等到 W3 加持久化时，存进去的就是旧数据——**这个顺序 W1 不定，W3 必返工**。

**W1 结束你应当能回答**：为什么 `emit()` 必须先更新 state 再叫 listener？——用自己的话，不用术语。

### 第 1 格：`async` / `await` / 事件循环
- 入口不是"讲 async 语法"，而是**接上你已经知道的因果链**：特别课 A 里的"跳转"，在 I/O 场景下为什么会阻塞整个程序。
- 产出 `test_async.py`：**并发**发起两个请求，总耗时明显小于串行。
- 验收：你能说出"等待的时候程序去干什么了"。
- 这一格要碰到的东西（按需展开，不漏不赶）：`async def` / `await` / 事件循环 / `httpx` 基本调用 / 从 `requests` 换到 `httpx` 的差异。

### 第 2 格：异常传播 + 任务注册表
- 产出 `test_tasks.py`：一个后台任务故意抛异常，**主流程不持有它的返回值**。
- 验收：**你必须能看到它**。如果你看到的是"什么都没发生"，这一格就没过。
- **主动触发**（别等它偶然发生）：在该任务 `await` 期间调用 **`gc.collect()`**，看它是不是**没跑完就消失了**；对照组 = 存进注册表后重跑，正常执行。见 §5.4 第 2 条。
- 这一格直接对应坑 2。

### 第 3 格：事件系统骨架 + `emit` 顺序定型
- 产出 `agent.py` 的 `emit()` 函数 + 两个 listener（一个打印 state，一个记日志）。
- 验收：日志能证明**两个 listener 看到的是同一份已更新的 state**。
- 这一格直接对应坑 3，**它是 W3 不返工的前提**。

## 10. 简历策略（"第二个目的"落地成可执行动作）

**不要罗列功能。** 面试官对"我写了个 agent 支持 10 个工具"无感，对下面这些会追问：

| 准备什么 | 为什么这就是优势 |
|---|---|
| **一份《我踩过的 5 个坑》**（W5 产出） | 只有真写过的人才知道这些失效模式——**这是最硬的能力信号** |
| **一次真实的排错**：会话第二次请求 400 → 定位到 `reasoning_content` 漏传 | 展示"读文档 + 读报错 + 定位根因"的完整链路 |
| **一次主动的设计决策**：为什么 `edit` 用 search-and-replace | 展示你能解释设计取舍，而不是照抄 |
| **一张结构图 + 能脱稿讲 20 分钟** | 大多数候选人的 agent 项目讲不清自己代码的结构 |
| **成本账**：缓存命中/未命中差几十倍，你怎么利用它 | 展示你知道这东西在真实场景里**要花钱** |

**面试必问、必须能答的 6 问**（提前准备）：

1. agent 循环的本质是什么？什么时候该停？
2. 流式输出除了"体感快"，还有什么好处？
3. 工具调用失败了怎么办？模型一直调用不存在的工具怎么办？
4. 上下文满了怎么办？为什么摘要要"追加"而不是"删掉旧消息"？
5. 你怎么控制成本？429 来了怎么办、什么错误**不该**重试？
6. **你和直接用框架（LangChain / 现成 agent）有什么区别？**

**先圈定"不做什么"，避免无限扩散**：
本地单用户 / 只对接 DeepSeek / 不联网搜索 / 不做多人协作 / 不接 MCP（除非最后一格有余量）。

**有余力再加、且只加这一件**：**最小 MCP 客户端**（连本机一个 MCP server，把它的工具转成 `registerTool` 调用）。
——理由：**2–3 格的成本换一个当前热门的简历关键词，且能亲手检验"协议适配"这件事有多机械**。放 W5 之后，不进五周保底范围。
