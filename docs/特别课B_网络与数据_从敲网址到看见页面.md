# 特别课 B · 网络与数据：从敲下网址到看见页面，中间发生了什么

> 授课：2026-09-21 前置串讲（原定 09-23）｜学员：深大计软大一｜教员：DeepSeek
> 定位：**特别课 A 的下一步，agent S0 的直接前置**。
> 本课不要求你会配服务器，只要求你能**用因果讲清楚**：一次请求出去、一次响应回来，各自经过了谁。

---

## 1. 一句话核心

> **网络 = 两台程序隔着机器说话；它们只靠"约定好的格式"互相理解。**
> **HTTP 就是那份约定；JSON 是正文的写法；API 是"哪些话允许说"的清单。**

---

## 2. 因果链：一次访问的七站

以 `https://www.baidu.com` 为例：

| 站 | 谁在干活 | 干了什么 | 关键点 |
|---|---|---|---|
| ① 域名 | 你 | 打了 `www.baidu.com` | **人记名字，机器只认数字** |
| ② DNS | 域名解析服务器 | 把域名翻译成 **IP**（如 `110.242.68.66`） | 这一步叫"解析"，是查表，不是魔法 |
| ③ 找路 | 路由器们 | 按 IP 把包一跳跳转发过去 | 中间经过十几台机器你不知道 |
| ④ 敲门 | TCP + 端口 | 跟对方 **443** 端口建立连接 | **IP 定位机器，端口定位程序**（一台机器上跑很多程序） |
| ⑤ 对话 | HTTP | 你**发请求**（要什么），它**回响应**（给你什么） | 请求/响应各有"头"和"体" |
| ⑥ 加锁 | TLS（HTTPS 的 S） | 把上面这段对话**加密**，并验证"对面真是百度" | 靠**证书**；证书由受信任的机构签 |
| ⑦ 渲染 | 浏览器 | 收到 HTML → 下载 CSS/JS/图片 → 画出页面 | 你看到的"页面"是浏览器加工后的结果 |

**要能自己讲出来的那一条**：**为什么要有 DNS？** 因为机器的地址是数字（IP），人的记忆是名字（域名）——DNS 就是这两套系统之间的翻译。**没有它，你得背 IP 上网。**

## 3. 请求与响应：谁在说话、说了什么

HTTP 的骨架只有四块（先记形状，不背字段）：

```
请求（你说的）                     响应（它回的）
───── 请求行 ─────                ───── 状态行 ─────
GET /s?wd=python HTTP/1.1          HTTP/1.1 200 OK
───── 请求头 ─────                ───── 响应头 ─────
Host: www.baidu.com                Content-Type: text/html
User-Agent: ...                    Content-Length: 12345
───── 空行 ─────                   ───── 空行 ─────
（GET 一般没有体）                  ───── 响应体 ─────
                                   <html>...</html>
```

- **方法**：`GET` = 我要读；`POST` = 我要交（提交/修改）。
- **状态码第一个数字看大类**：`2xx` 成功、`3xx` 搬家、`4xx` **你错了**（404 是"没这个东西"）、`5xx` **它错了**（服务器崩了）。→ **排查故障第一件事：看是 4 还是 5。**
- **`Content-Type` 决定你怎么读响应体**：是 HTML、是图片、还是 **JSON**。

## 4. 数据落地：从"打印出来"到"存起来"

你现在的程序：数据活在内存里，**程序一停就没了**（L10 之前就是这个状态）。
真正要用的东西必须**落地**——这就是数据库存在的理由：

| 存法 | 谁在用 | 优点 | 缺点 |
|---|---|---|---|
| 内存变量 | 你现在的程序 | 最快 | **一关就没** |
| 文件（txt / json / csv） | L10、L13 台账 | 简单、看得懂 | 一大就慢、多人同时写会打架、查一条要全读 |
| **数据库** | 服务器 / agent | 快、能扛并发、能按条件查 | 要装、要学 SQL |

> **一句话判据**：**"重启之后它还得在吗？多人同时动它吗？要按条件找吗？"** 三个里中一个，就该考虑数据库。

**服务器是什么？** 不是"一台特殊的机器"，而是**一个一直开着、等着别人来连的程序（进程）**。你本机跑一个 Python 脚本监听 8000 端口，它就是一个服务器——**这就是 S1/S2 里 agent 要扮演的角色。**

## 5. HTTP ≠ 人用的网页，API = 给程序用的入口

- **你点浏览器** → 人看网页（HTML）
- **程序发请求** → 拿数据（通常是 **JSON**）：`{"code": 0, "data": {...}}`

**API 是什么**：一个**约定好的入口清单**——"你可以问我这些，用这种格式问，我会这样回答"。
**agent 的本质就是这个**：agent 不点浏览器，它**发请求**。

三条以后天天要用的纪律（今天只立规矩）：

1. **密钥不进代码、不进仓库**：API Key 只记"它放在哪个环境变量/哪个密码管理器"，**永远不把值写进文件或对话**。
2. **接口文档是"最高法庭"**：参数名、返回字段以官方文档为准，不凭记忆（跟 OJ 的官方样例一个地位）。
3. **`GET` 与 `POST` 语义不同**：`GET` 应该"问一百次结果一样"（幂等），`POST` 是"会产生后果的动作"（下单、扣钱）。**别用 GET 干 POST 的事。**

## 6. 动手作业（明天课上核对；能测就测，测不了就记录下来）

- [ ] `nslookup www.baidu.com` 或 `Resolve-DnsName www.baidu.com` → 看清"② DNS"到底给了你什么（**这就是解析**）
- [ ] `ping www.baidu.com` → 看它被翻成了哪个 IP
- [ ] `curl.exe -I https://www.baidu.com` → 只看**响应头**，找 `HTTP/1.1 200` 和 `Content-Type`（`-I` = 只要头）
- [ ] 在看网页时按 `F12` → `Network` → 刷新 → 点第一条请求 → 看 **请求头 / 响应头 / 状态码**（浏览器就是最好的观察窗）
- [ ] ⚠️ 我（教员）今天这边 HTTPS 出网失败（`SEC_E_NO_CREDENTIALS`）——**以你的真实终端结果为准**；测不出来就写"没测到 + 报错原文"，不要照抄我的结论。

1. **复述**：在浏览器敲 `www.baidu.com` 到看见页面，中间经过哪几站？DNS 在第几站、干了什么？

3. **是非 + 理由**：网页显示 404，是**服务器坏了**还是**你要的东西不在**？

## 8. 这一课跟 agent（S0–S3）的关系

| S 段 | 它落在这一课的哪一块 |
|---|---|
| **S0** 结构草图 | ①–⑦ 全链：agent 站在"客户端"这一侧 |
| **S1** 会说话 | ④⑤⑥：给 DeepSeek 发 HTTPS 请求，读 JSON 响应 |
| **S2** 会动手 | ⑤ + A 课第 ⑤ 站：工具调用 = 自己发请求 / 自己跑一段程序 |
| **S3** 会记事儿 | §4 落地：会话存档 → 文件或数据库 |

> **A 课讲"程序怎么跑"，B 课讲"程序怎么跟远处的程序说话"。**
> **agent = 一个会跑、会说话、还会记事的程序。**
