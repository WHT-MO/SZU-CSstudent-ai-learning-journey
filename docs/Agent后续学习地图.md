# Agent后续学习地图

> 更新于2026-11-09。根据当前Python项目与学习记录整理，区分基础覆盖、待学主题和可选产品能力。

## 1. 已覆盖的基础

现有主线已覆盖模型请求、流式解析、工具说明与参数校验、执行及结果回填、Agent循环、事件显示、上下文预算与摘要、会话保存恢复、AGENTS规则与Skill按需读取、CLI及HTTP/SSE入口。进阶前五节还覆盖了多会话、主动停止、模型模块拆分、只读策略及结构化结果和结束原因。

当前可以继续从这个基础扩展能力，无需为进入新主题重做上述局部验收。部分能力有实际使用截图，部分只有静态审阅；两者按原记录区分。

## 2. 尚未系统展开的方向

| 方向 | 已有基础 | 后续内容 |
| --- | --- | --- |
| 运行中控制 | 一次任务的工具循环、后台Task、/stop，运行中追加指令和CLI后续任务队列已静态通过，单文件审阅的报告阶段恢复已实跑 | 更长工作流的阶段恢复 |
| 模型适配与可靠性 | DeepSeek、统一结果、按用途配置、摘要/流式有限重试及输出边界；任务计时、已报告usage累计与JSONL记录已实际成功 | 多供应商协议与运行时模型选择、输出恢复、按模型计费与更细粒度延迟 |
| 上下文与记忆 | 按行读取、搜索、整体增量摘要、会话存档；本地向量检索与多来源RAG问答已实际成功 | 保留近期多轮、滚动压缩、跨会话长期记忆、分段与检索质量、会话分支 |
| 外部工具与安全 | 本地工具注册、路径限制、只读策略；本地stdio MCP工具经模型选择、Agent执行与回填已实际成功 | 多服务配置与产品入口、浏览器/数据库工具、按操作或路径授权、提示注入处理与执行隔离 |
| 任务编排 | 模型自主选择工具；单文件审阅的结构化收集、代码校验和报告保存已实际跑通零问题路径 | 复杂任务分解、长任务的阶段恢复、多Agent的上下文与职责协调 |
| 工程与产品 | Mock入门、命令行、HTTP事件流、任务级运行记录、两份已知答案的审阅样例实跑 | 成套回归与更多任务类型的评测、细粒度链路记录、请求/会话并发隔离、部署与鉴权、界面和分发 |

会话树及JSONL已经讲过原理，这里指进一步实现；长期记忆则不同于把整段会话存盘，它还涉及选择、提取和再次检索有用信息。已有只读模式也是权限的一层基础，不等于全部执行隔离能力。

检索增强生成（RAG）指先检索相关资料，再把资料交给模型生成回答。MCP是用于连接AI应用与外部工具/数据的协议，参考[官方介绍](https://modelcontextprotocol.io/docs/getting-started/intro)。多Agent可以使用同一个模型，其区别在于上下文、职责和协调方式，并发请求本身不等于完整协作设计。

## 3. 建议顺序

[任务用量与运行记录](Agent进阶13_任务用量与运行记录.md)、[并行子任务与独立上下文](Agent进阶14_并行子任务与独立上下文.md)、[主Agent委派子任务](Agent进阶15_主Agent委派子任务.md)和[审阅工作流检查点](Agent进阶18_审阅工作流检查点.md)均有运行证据。[工具可见性与只读权限](Agent进阶16_工具可见性与只读权限.md)和[后续任务队列](Agent进阶17_后续任务队列.md)已静态通过。[审阅任务评测](Agent进阶19_审阅任务评测.md)已用已知缺陷和修复后的对照样例实跑。

这一顺序调整依据当前实现与之前审阅报告的误报经历：先学习任务产物及阶段控制，再扩展新的数据来源。它是教学选择，不表示所有任务都需要固定工作流、额外模型复核或向量数据库。

这是针对当前项目的教学选择，不是所有Agent都必须采用的固定路线。[进阶第6节](Agent进阶06_运行中追加指令.md#9-本节完成结果)没有剩余必做代码项；静态结论与实际运行证据继续分别记录，不额外重复局部验收。
