# 第 2 章第一小节：职责与调用关系

位置：Agent 架构中的“模型请求 → 循环控制 → 工具执行”。

目标：能沿着一次读文件任务，指出谁负责请求模型、执行文件操作、把结果放回历史并发起下一次模型请求。

教材依据：[第 2 章：三层架构](https://www.dgzhuya.com/modules/ch02-three-layer-arch/python)。本小节使用现有 Python 项目解释职责；文件拆分根据后续需要决定。

## 1. 职责是什么？

职责就是“这一段代码负责完成哪件事”。它帮助我们判断：新增或修改某种行为时，应该去哪里改。

当前先认识三个函数。

### `stream_message()`：取得一次模型回复

- 输入：现有 HTTP 客户端、请求消息、工具说明。
- 工作：构造并发送请求，解析服务器逐行返回的数据，累积文本和工具调用。
- 返回：`(message, completed)`，即回复消息和流是否完整结束。
- 返回消息里的 `tool_calls` 是模型提出的调用意图；实际文件操作由后面的执行环节完成。
- 当前代码也在这里逐段打印文本。这是现有实现，显示行为的分离在事件章节再讨论。

### `execute_validated_tool()`：执行一个已校验的工具

- 输入：调用 ID、实际工具函数、已经通过校验的参数。
- 工作：调用 `read_file` 等实际函数，处理超时和工具错误。
- 返回：一条 `role="tool"` 的结果消息。
- 真正的文件读取在 `tools.py` 的 `read_file()` 内；这个包装函数负责执行与结果封装。

### `run_agent()`：组织顺序和会话消息

- 输入：用户问题、最大工具调用轮数。
- 工作：准备消息，请求模型；根据回复处理工具或结束；把工具结果加入历史后再次请求模型。
- 当前函数返回 `None`；用户显示和会话保存通过执行过程中的操作完成。
- 决定“程序下一步调用哪个函数”和追加消息的代码位于这里。

## 2. 一次读文件任务怎么经过它们？

以用户输入“读取 a.txt，告诉我内容”为例，以下假设模型先要求读文件，再根据工具结果回答：

```text
run_agent：把用户问题加入 messages
    ↓
stream_message：第一次请求模型，取得 read_file 的调用意图
    ↓
run_agent：检查工具名和参数，准备有效调用
    ↓
execute_validated_tool：调用 read_file，返回 tool 结果消息
    ↓
run_agent：把 assistant 工具意图和 tool 结果加入 messages
    ↓
stream_message：第二次请求模型，此时输入包含文件内容
    ↓
run_agent：保存最终回复，结束本次运行
```

当前多个工具通过 `asyncio.gather()` 等待，返回值先汇总为 `executed_results`，然后按索引写进 `tool_results`。上图按单个工具展示职责。
