## 1. 一句话核心

> **CPU 只会做四件事：读一个数、写一个数、比一下、跳走。**
> **你写的所有 Python，最后都被翻译成这四件事的几百万次重复。**

---

## 2. 因果链：从源码到"跑起来"（六站）

| 站 | 谁在干活 | 干了什么 | 你踩过的痕迹 |
|---|---|---|---|
| ① 源码 | 你 | 在 `code\L17\sysin_demo.py` 里写下字符 | 文件大小、修改时间 |
| ② 启动 | Windows 加载器 | 按名字找到 `python.exe`，把它塞进内存 | `python` 能敲出来，靠的是 **PATH** |
| ③ 翻译 | Python 解释器 | **先编译**成字节码，再逐条解释 | 跑过一次才出现的 `__pycache__\*.pyc` |
| ④ 转换 | 解释器主循环 | 字节码 → **机器指令**（CPU 真正认识的那几十种） | CPU 不认识 `print`，只认识"搬数据/加/比/跳" |
| ⑤ 执行 | CPU + 内存 | 取指令 → 执行 → 取下一条；变量住在内存里 | `a = 5` 是"把 5 放进内存的某个格子" |
| ⑥ 落地 | 硬盘 / 屏幕 | 输出到终端，或 `open()` 写进文件 | L10/L13 的存档文件 |

**要能自己讲出来的那一条**：`__pycache__\*.pyc` 不是垃圾，是**第 ③ 站的产物**——它是 Python 版的"半成品"，下次直接拿来用，所以第二次跑同一个文件会快一点点。

---

## 3. 拿你自己的数据当证据（L16 实测，2026-09-19）

不做实验的通识课等于看视频。下面三个数都是本机量出来的：

| 量 | 数值 | 怎么量出来的 | 它说明了什么 |
|---|---|---|---|
| 启动 Python（什么都不算） | **0.095 s** | `Measure-Command { python -c "pass" }` | 第 ②③ 站有固定开销；启动不便宜 |
| 取一个字符 + 比一次 | **≈ 2×10⁷ 次/秒** | P1980：5,888,896 次 ÷ 0.25 s | 最便宜的操作，CPU 一秒能做两千万次 |
| 读一次硬盘 | **≈ 10⁻³ s 量级** | 对比上面两个 | 比"一次字符比较"慢 **几万到百万倍** |

> **这就是 O(n²) 为什么咬人**：不是"圈数多"，是**你在让 CPU 重复做那两千万次里的事，而它本可以去干别的**。
> 也是**为什么要有内存**：硬盘慢，先把数据搬进内存，CPU 才等得起。

**命令行的第一性原理**：命令行不是"另一种软件"，它是**你直接点菜的地方**——你打一个名字（`python`、`git`），Windows 就去找这个名字对应的 `.exe` 来跑。**GUI 是给你点的地方，CLI 是给你说的地方。**

## 4. 15 个命令：只记"它解决什么问题"

不背拼写、背问题。每一条都必须**自己敲一遍**才算学过（第 6 节有作业）。

| # | 命令 | 它解决什么问题 |
|---|---|---|
| 1 | `pwd` | **我现在站在哪**（相对路径的起点） |
| 2 | `ls` | 这一层里有什么 |
| 3 | `cd <目录>` | 换地方 |
| 4 | `cd ..` | 回上一层 |
| 5 | `cd ~` | 回家目录 |
| 6 | `mkdir <名字>` | 造一个空目录 |
| 7 | `rm <文件>` | 删文件（**没有回收站，删了就没了**） |
| 8 | `cp <源> <目标>` | 复制一份 |
| 9 | `mv <源> <目标>` | 搬家 / 改名（同一件事） |
| 10 | `cat <文件>` | 把文件内容打出来看 |
| 11 | `echo <文本>` | 打一行字；`echo x > f` 是写进文件 |
| 12 | `where.exe <名字>` | **这个名字到底指向哪个 exe** |
| 13 | `python <脚本.py>` | 叫解释器干活 |
| 14 | `Get-ChildItem` | `ls` 的 Windows 正经写法（PowerShell） |
| 15 | `Measure-Command { ... }` | 量一件事花了多久（后面还要用） |

> 🔎 第 12 条是"证据纪律"的落地工具：**不确定 `python` 是谁，就 `where.exe python`**。09-20 教员就是没做这一步、拿 `py -0p` 的**陈旧注册**当事实，被你当场纠正。

## 5. 路径三条铁律（L17 两个坑的正解）

1. **相对路径的起点 = 当前目录（`pwd` 说了算），不是"这个 py 文件在哪"。**
   人在 `code\L17` 里再写 `code\L17\x.txt`，就拼成了 `code\L17\code\L17\x.txt`——**路径拼成了两层，文件当然找不到**（09-17 实战）。
2. **绝对路径从盘符起算**（`D:\code\dsh\...`），**相对路径从脚下起算**。分不清就问 `pwd`。
3. **换目录就换世界**：同一个脚本、同一个相对路径，在 A 目录里跑得通、在 B 目录里就 `FileNotFoundError`——**代码没变，起点变了**。

## 8. 这一课跟 agent（S0）的关系

S0 要画的"agent 结构草图"里，**每一块都住在这条因果链上**：

- agent 进程 = 第 ⑤ 站（CPU + 内存里跑着的一个程序）
- 它读配置、写日志 = 第 ⑥ 站（硬盘）
- 它调用 API = 下面特别课 B 的"客户端发请求"
- 它启动一次工具（跑一段代码/一条命令）= **再走一遍第 ②–⑤ 站**

> **看不懂"程序怎么跑"，就只能背框架；看懂了，框架是自己长出来的。**
