## 1. 学习目标和工作方式

目标：能独立写出最小工具型 Agent，解释模型、循环、工具、消息和会话的关系，并能定位有代表性的故障。

- 用教材的章节顺序组织知识，用 `code/agent_v1/` 的 Python 实现验证原理。
- 当前已有功能作为对照材料；按理解缺口补课和做小变式。
- 分别记录“有实现”“有运行证据”“已独立写出并解释”，避免把三者混为同一进度。
- 纯讲解按完整主题一次给全，直接接到实际动手任务；动手任务按可独立实现的范围推进。小改静态检查正确即可继续，不逐步增加独立验证脚本。
- 新方法先解释用途、输入、输出、是否改变数据和一个常见失败点；不懂前置时先讲清，再布置实现。
- 学员负责项目和练习代码；教员负责讲解、审查、资料和进度记录。检查时优先阅读代码；运行和测试按学员当次要求执行。
- 可用时间沿用工作日约 3 小时、周末每天至少 6 小时的约定，按实际验收推进；小节可以拆分，掌握后可以加快。
- 收尾时统一提交和推送 Git，遵循 [教学机制与协作约定](教学机制与协作约定.md)。

## 3. 章节路线

### 第 1 章：总览——快速定位

- 问题：一个工具型 Agent 的最小组成是什么？完整产品额外承担什么？
- 对照：现有模型请求、会话状态、工具注册表、执行器和循环。
- 验收：能用一个具体任务指出这五部分各在哪里；若已清楚，直接进入第 2 章。

### 第 2 章：职责与依赖——已有首节复盘

教材：[三层架构 Python 对照页](https://www.dgzhuya.com/modules/ch02-three-layer-arch/python)。

- 先读各层分工和“是否需要三层”的讨论，再按需看类型递进。
- 先说明职责，再决定函数和文件如何划分。
- 当前对照：`stream_message()`、`run_agent()`、`execute_validated_tool()`；实际文件操作在 `tools.py`。
- 验收：追踪一次读文件任务，指出谁请求模型、谁执行工具、谁追加结果并决定下一次调用。
- 首节讲义：[职责与调用关系](Agent第02章_职责与调用关系.md)。

### 第 3 章：最小 Agent Loop——独立组织流程

教材：[Agent Loop Python 对照页](https://www.dgzhuya.com/modules/ch03-agent-loop/python)。

- 先读最简循环；用户插入指令、后续任务和复杂钩子按需求再展开。
- 学清一次模型调用与一批工具执行的边界，核对当前 `max_turns` 实际计数的含义。
- 独立产出：用固定的两次模型回复，跑通“第一次要求工具 → 返回工具结果 → 第二次回答”。先集中验证消息和循环。
- 当前讲义：[固定回复与最小循环](Agent第03章_固定回复与最小循环.md)。
- 验收：记录两次请求前的消息，解释为何第二次必须携带工具结果；能说明停止和轮数限制。

### 第 4 章：模型请求——稳定输入输出

教材：[模型调用](https://www.dgzhuya.com/modules/ch04-model-call)。

- 复盘客户端、请求、响应、非流式解析和流式累积的关系。
- 理解模型适配层：循环依赖明确的输入输出，供应商协议处理集中在请求层。
- 当前真实请求继续只对接 DeepSeek。两个模拟函数用于正常回答和持续工具调用两类场景；函数参数练习服务于可替换的请求实现与受控验证。多供应商支持按以后真实需求再安排。
- 首节练习：[把模型函数传给循环](Agent第04章_把模型函数传给循环.md)，用两个同步模拟模型练习函数参数与调用边界；后续统一异步约定接回 HTTPX。
- 复用已有 HTTPX mock 学习，分别保留五个基础场景，再补多段正文、工具参数分片、读取异常等变式。
- 区分流结束、生成停止原因、部分输出和请求失败；保留控制层需要的错误信息。
- 继续 429 → 成功练习，学习有限重试、递增等待、哪些状态应立即停止；流式重试还要考虑已输出内容和工具副作用。
- 验收：控制同一个核心循环使用固定回复或真实请求；用证据说明成功、中断、错误和取消分别如何传递。

### 第 5 章：工具系统——描述、校验、执行

教材：[工具系统](https://www.dgzhuya.com/modules/ch05-tools)。

- 对照 `tool_schemas.py`、`process_tool_call()`、执行包装函数和 `tools.py`。
- 首节练习：[工具执行依赖](Agent第05章_工具执行依赖.md)，用共享字典模拟先写后读，对照并行与顺序执行，再回到主程序决定调度方式。
- 解释参数说明、运行时校验、路径约束与实际文件操作各解决什么。
- 区分执行顺序与结果排列；先用独立只读调用和同文件修改的例子理解依赖。
- 根据理解确定简单调度规则；需要更细并发时再考虑按文件排队。
- 验收：有效调用能执行；有 ID 的工具错误能关联回模型；说明线程超时或取消等待后，底层操作是否真正停止。

### 第 6 章：消息系统——内部状态与模型边界

教材：[消息系统](https://www.dgzhuya.com/modules/ch06-messages)。

- 画清内部记录、模型请求消息和用户显示三个读者的需求。
- 区分 Pi 统一消息与当前 DeepSeek HTTP 消息，按适配层转换字段。
- 保留目前中文中断提示；自动重试等功能需要程序状态时，再引入相应内部字段。
- Python 项目讲义：[消息的三种用途](Agent第06章_消息的三种用途.md)，与第 5 章剩余说明一次讲清；不为纯讲解另设逐点确认。
- 验收：追踪 user → assistant 工具意图 → tool 结果 → assistant 回答；说明每条消息什么时候加入历史、下一次发送什么。

### 第 7 章：事件——接回实际项目

教材：[事件驱动](https://www.dgzhuya.com/modules/ch07-event-driven)。

- 从显示或记录工具执行过程的实际需求开始，把早期监听器练习接回主路径。
- 先做少量必要通知，再区分只读观察与需要等待结果的决策钩子。
- `agent.py` 的“顺序 await 监听器”是已有练习，不视为所有事件系统的统一规则。
- 首项实际任务：[工具执行通知](Agent第07章_工具执行通知.md)，学员建立通知模块并把开始事件接入 `execute_validated_tool()`；不新增独立测试脚本。
- 验收：新增一个显示或日志消费者能观察运行过程，并说明监听器异常、等待和清理的处理方式。

### 第 8 章：上下文工程——控制进入模型的信息

教材：[上下文工程](https://www.dgzhuya.com/modules/ch08-context-engineering)。

- 先按任务选择读取策略，完整说明小文件整读、结构/搜索定位后按需读取、全面审阅覆盖的适用范围与调用、遗漏成本。
- 首项动手：[读取策略与行范围接口](Agent第08章_大工具输出与分段读取.md)，read_file 增加 start_line=1、end_line=None，能直接跳转相关行；原 4000 字符顺序分页练习撤下，不要求先实现再改写。
- 随后接带行号的简单搜索，以及单次输出体积兜底，形成定位、展开、必要时补读的流程。结构概览按需求增加，不把复杂索引作为当前前置；行范围能力不能单独保证结果体积上限。
- 学习请求预算，区分 token 粗估与 API 实际用量。当前 Python 项目的具体练习安排为：字节保护完成后读取 usage 观察实际消耗，再整理 tools、输出预留与误差余量。请求预算与实际用量的区别是原计划内容（已提交版本789023f），这项动手任务是围绕当前实现细化的教学安排；本地精确分词按模型兼容性与实际需要再接。当前 JSON 字符数 //4 仅为粗估。
- 检查：输出额度、提示和后续读取路径一致，模型知道结果是否完整、怎样继续。局部修改静态检查正确即推进，不新增独立验证脚本；需要运行或查看实际请求时按学员要求安排，已有证据与未运行事项分开记录。

### 第 9 章：压缩——整理当前整体摘要策略

教材：[上下文压缩](https://www.dgzhuya.com/modules/ch09-compaction)。

- 当前继续采用整体摘要；先处理最新用户要求的保留、摘要复用和输出预算。
- 首项实际任务：[摘要与当前任务](Agent第09章_摘要与当前任务.md)，以最后一条user为分界，旧历史整体摘要，当前轮次保留原始user/assistant/tool消息；先实现切分，再接准备请求的成功/失败流程。
- 区分完整会话档案与下一次请求使用的摘要视图。
- 滚动摘要、保留近期轮次和复杂切点留到该小节有需要时学习。
- 检查：消息切分、摘要覆盖范围与请求视图一致，摘要失败有明确后续行为，原始档案仍可回溯；局部静态正确即推进，不新增小阈值运行或复述门槛，实际运行仅按学员明确要求安排。

### 第 10 章：会话——存储、恢复与分支

教材：[会话管理](https://www.dgzhuya.com/modules/ch10-session)。

- 先区分存储介质与逻辑结构；当前单个 JSON 文件继续作为基础实现。
- 理解追加日志、会话标识、当前分支和请求视图；实现范围按实际需求选择。
- 验收：保存和恢复能重建下一次所需上下文；有分支需求时再演示如何保留两条路径。

## 4. 持续保留的工程要求

- 文件工具限制在 `code/agent_v1/workspace/` 内，文件修改操作说明匹配条件与副作用。
- 工具调用与结果能关联，循环有停止边界，取消能向上传递。
- 学习中的每个关键场景留下可重现的输入、返回值与定位说明；由学员实施和运行。
- 付费请求沿用 ¥100 上限。用量、成本记录放在模型请求和上下文章节完成；单价与接口细节按实现当天官方资料核对。
- 逐步整理项目运行说明、依赖和示例，让别人能复现已声明的能力。

后台任务回收等已有实验作为专题参考；终端界面、多模型全适配、完整插件系统、多 Agent 和复杂会话树按后续项目需求安排。
