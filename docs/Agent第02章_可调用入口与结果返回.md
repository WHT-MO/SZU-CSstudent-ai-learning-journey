## 1. 为什么现在做

当前run_agent已经能准备上下文、调用模型、执行工具、保存会话。终端通过stream_message中的打印显示回答，但run_agent本身返回None。另一个Python函数即使写下result = await run_agent(...)，拿到的也只有None，无法直接使用最终回答。

终端显示与函数返回是两件事：print把文字写到输出窗口，return把值交给调用者。让run_agent返回最终消息后，其他脚本能够读取其content或保存到自己的结果中。这是给现有入口增加一个明确的调用约定，尚不代表已经完成所有显示逻辑的分离。

此前最小练习只展示三种流程，打印并退出符合练习目标。本次新增目标是让外部调用者获得结果，因此增加返回值有了具体用途；首版审阅报告不能据此倒推原练习必须实现这一能力。

## 2. 当前返回约定

| 本次运行的结果 | run_agent返回值 |
| --- | --- |
| 模型完整结束，且没有继续请求工具 | 已保存的最终assistant消息字典 |
| 请求失败、响应不完整、达到工具上限或既有其他提前退出 | None |

返回字典沿用已有message结构，例如role与content；当前不新增状态类或另一套结果格式。None暂时只表达“没有取得完整的最终回答”，以后调用方确实需要区分原因时，再扩展约定。

“没有工具调用”本身不足以说明成功：现有代码先判断completed，再进入最终回答分支，因此只有完整回复才返回给调用者。响应不完整时，既有逻辑可能保存部分文字，保存部分记录与取得完整最终结果分别处理。

## 3. 当前动手

修改code/agent_v1/agent_runner.py中的run_agent：

1. 将返回类型注解从None调整为dict | None。注解说明约定，实际返回行为仍由函数体决定。
2. 找到完整且无tool_calls的最终回答分支（当前第663至666行）。追加消息、保存会话完成后，将这条message返回给调用者。

其他已有退出路径自然返回None，符合上表。当前main只等待运行，Python允许调用者暂时忽略返回值；流式过程已经显示正文，再打印一次返回的content会重复显示。
