## 1. 需求定稿（自己定的，教员追问了 7 轮）

- **终端循环菜单**：`1 = 打卡 / 2 = 看记录 / 0 = 退出`；按键就当作"点击"的替代。
- **明说推迟的功能**（当时就写清了，不当遗漏）：
  - 图形界面 → L12 之后｜**存文件 → L10 之后**（这就是 L10 的钩子）
  - 真实系统时间（`datetime` 属模块课）｜多用户｜图表
- **"今天"从哪来**：没有时间模块，就**程序启动时问一次**"今天是第几天"（沙盘）。
- **连续天数规则**（三条）：
  1. 昨天打过 → **+1**
  2. 跳过 ≥1 天 → **归 1**（断了重来）
  3. 今天已经打过 → 提示一下，天数**不变**
- **验收 4 条**：连打三天 = 3；跳一天 = 1；同一天两次 = 不变；不存盘。

## 2. 迭代轨迹：四版才成形

| 版本 | 形状 | 结果 |
|---|---|---|
| v1 | 一次性 `if` 判断 + 直接打印 | 无状态、无循环菜单；断签那一支直接结束程序 |
| v2 | 包成函数 `daka()`，函数里写 `last = today` | 💥 **`UnboundLocalError`** |
| v3 | **去掉函数、平铺** | ✅ 四条验收全过（2/3/4、归 1、不变、新用户 1） |
| v4 | 改回函数版 `def daka(last, d)` + `return last, d` | ⚠️ 会接返回值了，但引入新 bug（见 §3） |

### v2 的 `UnboundLocalError` 是怎么来的

这是 L07 作用域的**反面**：函数里**只要对某个名字有赋值**（`last = today`），Python 就把 `last` 当成**这个函数的局部变量**；可函数里**先**读了它（拿它和 `today` 比较），它此刻还没被赋值 → 直接**报错**。

**教训**：想改外面的状态，不能靠"在函数里赋值"，只能**把值当参数传进去、再用 `return` 递出来**。

v3 用"去掉函数、平铺"绕过了作用域，四条验收全过——**用结构规避问题**是聪明的做法。

## 3. v4 留下的三笔账（第二天逐条修掉）

1. **核心坑**：`d` 的初值只处理了一种情况，而且**写在循环里每轮重算** → 把函数内 `d = d + 1` 的累积**覆盖**了 → 症状是"**看记录**"永远比"打卡后"**少 1**。
   - 方向：循环外一次性算全三种初值（接上 / 断签 / 今天已打），循环内**不再重算**。
2. **`last > today`**：警告之后没有停止流程 → 用户接着敲 1 **静默无反应**（比报错更难查）。
3. **"继续请按 0"与菜单"0 = 退出"语义冲突**。
4. 机制 4 要求的"**不看资料画出数据流图**"**未做**（学员决定跳过，见 §6）。

## 4. 学员的四处自修（2026-09-13，全部自己发现 + 自己改）

| # | 问题 | 修法 |
|---|---|---|
| ① | **新用户误判**：`last == today - 1` 在 `last = 0`（从没打过卡）时**也成立**（`0 == 1-1`）→ 新用户一进来"看记录"就报"已连续打卡 1 天" | 条件补 `and last != 0`——用 **`last = 0` 当哨兵值**表示"从未打卡"，把它排除在"昨天打过"之外 |
| ② | **今天已打卡的口径**：已打卡但没续跑时显示不出 1 天 | 在 `d == 0 and last == today` 时补成 `d = 1` |
| ③ | **读操作带副作用**：按 2 看记录时把 `d` 由 0 改成 1 | 把 `d` 的初值整段搬到每轮**启动处**（与 `last == today - 1` 那支放一起，并补 `last == today` 分支），**看记录分支恢复为纯只读** |
| ④ | **换天时 `today` 不再被校验** → 输入倒退会把非法日期带进下一轮 | 主循环开头补 `while last > today:` 复核 |

> 哨兵值是什么：拿一个**正常数据里不会出现的值**（这里是 `last = 0`，因为"第 0 天"不存在）当"特殊状态"的标记。

## 真实案例：`code\L08\kaoqin.py` 代码地图（43 行）

| 行 | 内容 |
|---|---|
| 第 2 行 | `def daka(last,d):` —— 菜单函数，状态**靠参数进、靠 return 出** |
| 第 3–19 行 | 菜单循环：第 5 行"昨天打过 → `d = d + 1`"、第 9 行"断签 → `d = 1`"、第 13 行"今天已打卡 → 只提示"、第 15–16 行"看记录"、第 17–19 行"按 0 退出" |
| 第 20 行 | `return last,d` —— 把改过的状态交回主程序 |
| 第 21–25 行 | `def check(today):` —— 第 22 行 `while last > today or today == 0:`…**注意它读的 `last` 是第 28 行的全局变量** |
| 第 26–28 行 | 启动段：`d = 0`、`t = 0`、`last = int(input("上次打卡第几天："))` |
| 第 29–43 行 | 主循环：第 30 行问"今天是第几天"→ 第 31 行 `check` 校验 → **第 32–37 行一次性算全三种初值** → 第 38 行 `last,d = daka(last,d)` **接住返回值** → 第 39–43 行"继续请按 0" |

两个要点：
1. **看记录分支（第 15–16 行）只 `print`，不改任何状态**——这就是修掉副作用后的样子，值得记住。
2. `check()` 第 22 行**偷偷依赖了全局变量 `last`**：函数从外面"顺手拿"了一个它没写在参数里的东西。现在能跑，但它让"数据从哪来"变得看不出来——这正是 L11 要治的病。

## ⚠️ 常见坑 / 真撞过的报错

1. **`UnboundLocalError`**（v2）：函数里有赋值 + 先读该名字。
2. **"有 `return`、没人接"**（v4 首版）：`return` 递出去的值必须用 `=` 接住，否则等于**丢弃**。
3. **"不报错的错"最贵**：`last > today` 时敲 1 **静默无反应**——没有报错，但程序什么也没干。凡是"输入了却没反应"，先去查条件分支有没有覆盖到这种情况。
4. **哨兵值当普通值用**：`last = 0` 被 `last == today - 1` 误判成"昨天打过"（新用户 bug）。
