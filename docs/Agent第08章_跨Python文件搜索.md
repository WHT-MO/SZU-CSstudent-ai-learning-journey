# 第8章方案说明：跨文件搜索与现有工具

> 2026-10-23。原安排的Python专用搜索工具练习已撤下，尚未实现，也不作为后续学习前置。

## 1. 现有工具能做到什么

| 工具 | 当前实现 |
| --- | --- |
| `list_files` | 列出一个目录的直接子项名称 |
| `search_file` | 搜索一个已知文件，返回匹配文本、路径和行号 |
| `read_file` | 读取一个已知文件，支持指定行范围 |

因此可以先列目录，逐个搜索候选文件，再读取命中位置的上下文。遇到子目录时继续列目录即可，不必为了完成这个流程另造一种工具。

## 2. 批量搜索的实际价值

目录搜索可以把多次列目录和单文件搜索合并为一次工具调用，减少Agent请求模型和调用工具的往返次数。文件较多、定位频繁时，这种便利才值得实现；当前无需为此增加练习。

限定只搜Python文件是此前为了缩小练习范围作出的选择，并非Agent架构要求。文档和配置也可能需要搜索，不应每种文件类型各增加一个工具。

后续确有需要时，优先考虑扩展现有搜索工具，让它支持目录，并把`*.py`等文件模式作为筛选条件。届时再根据实际任务决定接口和实现范围。
