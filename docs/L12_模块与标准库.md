## 0. 开课先补的 1 分钟关节「谁依赖谁」
同一个 `check()`，三处写法：

| 文件 | 行 | 写法 | 依赖从哪来 |
|---|---|---|---|
| `code\L08\kaoqin.py` | 第 22 行 | `while last > today …` | **隔空够全局变量**（签名里没有 `last`） |
| `code\L10\kaoqin.py` | 第 75 行 | 同上，原样继承 | 同上 |
| `code\L11\kaoqin.py` | 第 78 行 | `while self.last > self.today …` | **`self` 是递进来的第一个参数** → 依赖写在签名上 |

判据（背下来）：**函数能看见的只有三种东西 —— ① 递进来的参数 ② 自己造的局部变量 ③ 外面的全局变量。第③种最危险：它不在签名上，调用者光看签名看不出来。**

## 2. `import` 的三种写法（重点在"名字"）
- `import math` → 用 `math.sqrt(9)`：**带模块名前缀**，撞名少 → **默认用这个**。
- `from math import sqrt` → 直接 `sqrt(9)`：省字，但把名字搬进你的命名空间 → 撞名风险。
- `import math as m`：别名（约定俗成，将来 `import numpy as np`）。
- 铁律：**`import` 之前那个名字不存在** → `NameError: name 'os' is not defined`（学员 09-17 亲手撞出来的第一条）。

## 3. PATH：命令为什么能敲 / 不能敲
- 敲 `git` 回车，系统做的是：拿 PATH 里那一串文件夹，**从前往后挨个找 `git.exe`**（Windows 还会试 `.exe/.cmd/.bat`）。
- `where.exe` 是侦探：`where.exe python` / `where.exe git` / `where.exe javac`。
- **今天最值钱的一条（反直觉）**：`D:\app\Java\bin` **明明在 PATH 清单里**，`where.exe java` 照样找不到 —— 因为**那个文件夹里没有 `java.exe`**。
  → **PATH 只负责"去哪几个文件夹找"，不保证"那里真有这个程序"。**
- 三个解法：① 敲全路径 `& "D:\code\git\Git\bin\git.exe" --version`；② 把文件夹加进 PATH；③ 安装时勾 "Add to PATH"。
- 在 Python 里看：`os.environ["PATH"]`。**环境变量 = 操作系统给每个进程准备的"公共便签"**，程序启动时继承一份。
- ⚠️ **本机勘误（09-17，教员侧第 8 次）**：仓库里从 09-06 起记着"Git 未加入 PATH，所以 `git` 敲不了"——**是错的**。实测：`where.exe git` → `D:\code\git\Git\cmd\git.exe`，裸 `git --version` 可用，且该目录写在**机器级 PATH** 里（学员自己打印的 PATH 第 10 条就是它）。README / 学员档案已改正。

## 4. 模块课的正主：让存档"跟着脚本走"
- 相对路径的基准是 **cwd**（你敲命令时所在的目录），**跟 .py 放在哪无关** → 换个目录跑，存档就落在那个目录里（L10 遗留的问题）。
- **`__file__`**：**这个 .py 文件自己的路径**（Python 免费发的变量，不用 import；3.9+ 起必是绝对路径）→ **不随 cwd 变**。
- **`os.path.dirname(路径)`**：取这个路径所在的**文件夹**；**`os.path.join(文件夹, 文件名)`**：拼成一个路径（**别手写 `\`**）。
- 成品 `code\L12\kaoqin.py`：`__init__` 里算一次

  ```python
  self.path = os.path.join(os.path.dirname(__file__), "打卡状态.txt")
  ```

  **三处 `open()` 共用**（对应 L11 版第 67 / 83 / 88 行）。→ 这就是"**同一个决定只写一次**"：改一处、三处生效。
- 判据：**`__file__` = 文件在哪；`os.getcwd()` = 人在哪。**
- 验收（教员实跑，对照 L11 原版）：在 `D:\code\dsh` 里跑 L12 版 → 存档落在 `code\L12\`，`D:\code\dsh\打卡状态.txt` **不出现**；同一串输入喂两版 → **输出逐字相同**、存档都是 `2 2`。

## 5. 读 traceback 的固定动作
1. 看**最后一行**：什么错；
2. 往上看 `File "..."`：出错时谁在调用谁；
3. **先扫一眼有没有你的文件名** —— 有 = 你的代码出问题（还带行号和 `^^^` 箭头）；没有 = 问题在"**跑它的方式**"。

实例（09-17 真撞）：VS Code 里按 **F5（调试）** 报

```
ConnectionRefusedError: [WinError 10061] 由于目标计算机积极拒绝，无法连接。
```

命令长这样：`python3.12.exe ...\debugpy\launcher 49430 -- tansuo.py` —— 这是 debugpy 调试器要**回头连上 VS Code 的调试端口 49430**，没人接。**整段 traceback 里没有 `tansuo.py`** → 代码无辜。
正确做法：VS Code 里用 ▷ **Run Python File**（运行），或终端里 `python tansuo.py`；一定要调试就 `Developer: Reload Window` 后重试。

## 6. 三种"名字 / 值"的错，别混
| 报错 | 人话 | 触发条件 |
|---|---|---|
| `NameError` | **没这个人** | 读一个从没定义过的名字（忘了 import、名字打错） |
| `UnboundLocalError` | 工位在，人还没上班 | 函数里**有对该名字的赋值** → 它成了局部变量，却在赋值前被读 |
| `ValueError` | 人对了，给的数不对 | `int("abc")`、`not enough values to unpack` |

## 7. 真撞过的坑（09-17）
1. **`sorted(x)` 的返回值没人接**：`set` 本来就无序，不接住 → 打印出来还是乱的。
   双胞胎记牢：**`sorted(x)` 返回新列表（原对象不动）／`x.sort()` 原地改、返回 `None`**。
2. **`join` 要"一整批"**：对**单个数字**调用 → `TypeError: 'int' object is not iterable`；而且里面的元素**必须全是字符串**（数字先 `map(str, …)`）。它还是**分隔符（字符串）的方法**，不是列表的方法。
3. **硬编码路径**：`"D:\..."` 要加引号、`\` 还有转义含义（一般写 `r"D:\..."`），而且换个文件夹 / 换台电脑就崩 —— 这正是 `__file__` 存在的理由。
4. **对照验收没对齐起跑线**：`code\L11\` 里残留的 `打卡状态.txt` 让两版"起点不同"，输出当然不同。→ **对照实验之前先对齐初始状态。**
5. **AC 了不等于落库**：P1059 的定稿当时只在草稿区。产物要进 `code\Ln\`（**同类第 2 次**，第一次是 P5711）。
