## 2. 容器四件套（全部已学）

```python
lst = [1, 2, 3]          # list  排队名单：有序可改
tup = (1, 2, 3)          # tuple 封条盒：有序不可改
st  = {1, 2, 3}          # set   磁贴盒：无序唯一
dct = {"a": 1}           # dict  点名册：键→值
# 空容器：[] 空 list｜set() 空 set ｜{} 空 dict（不是空 set！）
single = (1,)            # 单元素 tuple 必须加逗号
lst[0]; tup[-1]          # 下标取（有序的都能下标）
lst[1:3]                 # 切片【09-20 转正】：从哪开始、到哪为止（不含）、每步走几格
lst[:2]; lst[2:]; lst[-2:]   # 前两个 / 从第 3 个到末尾 / 最后两个
lst[::-1]                # 步长负 = 从最右往左走 → 倒序（返回【新】对象，原列表不变）
x in st                  # "在不在"：set/list 可；dict 查的是键
for k, v in dct.items(): # 键值一起遍历（已学）
```
> **为什么 `for k in dct` 拿到的是键**（09-11 讲透）：字典的"身份"就是键——像通讯录先看名字列表。所以"逐个"默认给键，**没有第二种默认**。
> **`items()` 只解决一件事**：把每一对打包成 `(键, 值)` 交出来。`for k, v in ...` 的两个变量就是**拆包**（和 `a, b = (1, 2)` 同族）；只写 `for k in dct.items():` 拿到的是整个配对。
> **`items` 后面的 `()` 是"执行扳机"**；`d.` 是告诉它"打包哪个字典"。（对比：字符串/列表没有 `items`，写了会 AttributeError。）

## 4. 字符串清洗套路（方法均为 L05 已学列表内）

```python
s = input().strip().lower()      # 去首尾空白 → 变小写（链式）
```

```python
total = 0

    total = total + x        # ① 最啰嗦、最清楚（先学这个）
```

## 7. 函数 def（L07 已学）

```python
def average(a, b, c):        # def = 造工具（只造不跑）；a b c 是参数（形参）
    total = a + b + c        # 函数体：缩进的这几行，每次调用整段跑一遍
    return total / 3         # 交货：把结果【递出去】（能接住、能再算）
print(average(90, 80, 100))  # 调用：写 名字(...) 才真的执行

def f1(a, b):
    print(a + b)             # 只"喊给人听"，没有 return
r = f1(1, 2)                 # → r 是 None（没 return 的函数自动交 None）
```
> - **`print` / `.append` 都"只做事不交货"**（调用处拿到 `None`）；`return` 才是交货。
> - **返回多个值**：`return x, y` → **打包成元组**；调用处 `w, d = week(5)` → **拆包接住**（同 `a, b = (1, 2)`）。
> - **`return` 交出去的值若要留待后用，可以用 `=` 接住**；也可以直接用于 `print(f())` 或其他表达式。不使用时返回值被丢弃。
> - **作用域**：函数体里造的局部变量出了函数就不能直接访问；函数内给参数名重新赋值不会改变外面的变量绑定。但如果参数引用可变对象，在函数内修改该对象（如 `lst.append(x)`），外面也会看到变化。
> - 小技巧：`print(a, *week(b))` 的 `*` = **把容器就地摊开**（能用，但显式接住更好读）。

## 8. 易混对照表（全部基于已学内容，写完自查）

| 混淆点 | 正确 | 错误/坑 |
|---|---|---|
| 赋值 vs 相等 | `==` | `=` |
| input 类型 | `int(input())` | `'18'+1` 炸 |
| 大小写转换 | `s = s.upper()` | 不接住 = 白干 |
| range 终点 | `range(1, n+1)` | `range(1, n)` 少了 n |
| 空集合 | `set()` | `{}`（是空 dict） |
| 单元素元组 | `(1,)` | `(1)` |
| 字典取值 | `dct.get(k, 默认)` | `dct[缺的k]` → KeyError |
| 拆字符 vs 拆词 | 先 `.split()` | 忘 split 直接处理整串 |
| 引号 | 英文半角 `"` `'` | 全角引号 → SyntaxError |
| 下标起点 | 第 1 个是 `[0]` | 从 1 数 → 错位 |
| dict[键] 的读写 | `=` 左边=写 | = 右边才=读（刚锁的关键） |
| range 三参 step | 终点只要 > 最后一个目标值即可（`range(3,13,3)` 与 `range(3,15,3)` 同结果） | `range(3,12,3)` 会**吃掉** 12；`range(3,3,3)` → 空 `[]` |
| while 推进 | 循环体里必须有 `h -= 1` 之类让条件终会变假的动作 | 条件恒真 → **死循环**刷屏（09-11 实撞） |
| map 逐个对象 | `map(int, x)` 对 x 的**每个元素**处理 | 直接喂整行文字 → **逐个字符**（`"12"` 变成 1 和 2）；必须先 `.split()` |
| 空容器取最值 | 先确认里面有数 | `max([])` → `ValueError: max() iterable argument is empty`（09-14 学员实跑） |
| 保留两位小数 | `f"{x:.2f}"`（管【显示】，位数不足补 0） | `round(x, 2)` 只管数值 → `round(2.0, 2)` 打印仍是 `2.0`（P5726：第 3 次格式类错） |
| 遍历字典 | `for k in d` → **键**（字典的身份就是键） | 以为拿到值；要键值一起用 `for k, v in d.items()` |
| 切片终点 | `s[1:3]` **不含**下标 3（前闭后开，同 `range`） | 以为含 3 → 多取一个 |
| 切片步长符号 | `s[::-1]`（负步长 = 从最右往左 → 倒序） | **`s[::1]` 只是复制一份，不是倒序**（09-20 学员实答错一次） |
| 切片 vs 下标 | 切片返回**新对象**，原数据不动 | 以为切片是"原地改" |

## 12. Agent v1：异步任务与事件通知（09-24 已实践）

```python
import asyncio

async def work():
    await asyncio.sleep(1)      # 当前协程等待；事件循环可运行别的已就绪任务
    return "done"

async def main():
    task = asyncio.create_task(work())  # 创建并安排任务；不会在这一行等它完成
    result = await task                 # 等待完成，并取得返回值或收到异常
    return result

asyncio.run(main())                # 从同步程序入口启动事件循环
```

- `await work()` 两次依次写是串行等待；`await asyncio.gather(work(), work())` 可安排两次等待重叠。学员在模拟等待中测得约 2 秒与 1 秒；实际网络耗时不能照搬这个数字。
- `asyncio.sleep()` 会让出事件循环；`time.sleep()` 在同一线程中阻塞它。`await asyncio.sleep(0)` 可让出一次运行机会，不需要为了这一点固定等 0.1 秒。
- `task.add_done_callback(callback)` 注册完成回调；`callback` 接收**一个 Task 参数**。若任务可能失败，回调读取 `finished_task.exception()` 才能取得并处理异常；仅打印“完成”不会处理异常。长期运行的后台任务可放进 `set()` 保留强引用，完成后 `discard`。无强引用的待处理任务**可能**被回收，实际是否出现警告取决于运行情形。
- `loop = asyncio.get_running_loop()` 取得当前事件循环；`future = loop.create_future()` 创建未完成的 Future。`await future` 会等待；其他代码调用 `future.set_result("ready")` 后，等待者取得 `"ready"`。Task 不能手动 `set_result()`；它由协程执行来完成。

```python
state = {"messages": []}            # 字典有一个键；len(state) 是 1
state["messages"].append("hello")  # 消息列表现在有一项
count = len(state["messages"])     # 消息数是 1

listeners = [show_state, record_state]  # 存函数对象；此处不加 ()

async def notify():
    for listener in listeners:
        await listener(state)           # 在异步函数内逐个调用异步监听器
```

- 事件顺序：`emit(message)` 先更新 `state`，再通知监听器；反过来每次监听器都读到旧状态，最后一次追加会漏出日志。
- 历史日志若只需记录消息数，存 `len(state["messages"])` 这样的当时值；直接存可变 `state` 引用，之后改状态会让旧日志看起来也变了。
- `{ "messages" }` 是集合，`{"messages": []}` 才是字典。`len(state)` 数键，`len(state["messages"])` 数消息。
