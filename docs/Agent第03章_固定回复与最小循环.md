# 第 3 章：固定回复与最小循环

当前位置：Agent Loop 中的“调用模型 → 执行工具 → 带结果再调用模型”。

目标：学员独立组织这条消息链。现有 `agent_runner.py` 用作对照。

教材：[第 3 章 Python 对照页](https://www.dgzhuya.com/modules/ch03-agent-loop/python)。

## 第一小步：用固定回复代替模型

循环需要模型函数提供一条 assistant 消息。先用普通 Python 函数返回预先约定的消息，控制每次发生什么，便于专注消息传递。

```text
messages → fake_model(messages) → assistant 消息
```

这里输入仍是历史消息，输出仍是模型回复的形状。这个小函数承担本练习的模型角色。

### 学员实现任务

在 `code/agent_v1/minimal_loop.py` 自己写 `fake_model(messages)`。本练习约定传入的消息列表非空，末条为 user 或 tool 消息。

- 最后一条是 user：返回下面的工具调用意图。
- 最后一条是 tool：返回一条普通 assistant 消息，其 `content` 为“笔记内容：”加上收到的工具结果文本。

第一次的固定回复数据：

```python
{
    "role": "assistant",
    "content": "",
    "tool_calls": [
        {
            "id": "call_1",
            "type": "function",
            "function": {
                "name": "get_note",
                "arguments": "{}",
            },
        }
    ],
}
```

`get_note` 是本练习的简单工具名称，参数为空。模型函数只返回调用意图。

如果输入最后一条工具消息的 `content` 是 `hello`，预期第二次回复为：

```python
{"role": "assistant", "content": "笔记内容：hello"}
```

这一小步先提交函数供检查。重点是：返回内容由传入的历史决定，而不是在模型函数里更新历史或执行工具。

## 停止边界：最大工具执行轮数

当前正常退出依赖模型返回不带工具调用的回答。如果模型持续要求工具，还需要程序自己限制执行轮数。

- `max_tool_rounds`：允许执行工具的最大轮数。
- `tool_rounds`：已经进入工具执行的轮数，初始为 0。
- 每轮先处理模型普通回答的结束条件；如果有工具，在执行前检查轮数上限。
- 达到上限则提示并停止；未达到时才计数和执行工具。
- 工具返回结果之后仍可请求模型取得最终回答；这次普通回答不增加工具执行轮数。

学员在现有循环上实现。先用固定模型回复确认两种行为：上限 0 时一次工具都不执行；上限 1 时执行一次工具，随后仍能取得正常回答。之后再构造模型持续要求工具的例子，确认执行次数不会超过上限。
