## 3. 新知识点 / 结论
- **文档按读者拆**：一份文件同时服务三种读者时，三种需求互相打架（门面要短、手册要全、纪律要细）→ 按读者各成一份，README 只留**导航**。
- **搬家要带指针**：改了结构，就要把**所有指向它的引用**一起改（本次：`memory/README.md` ×2、`docs/学习资料精选_TOP5.md` ×1）。
- **但"指哪儿改哪儿"**：本次**刻意不动**所有指"**根 README 日历**"的引用（`docs/职业路线…:4`、`memory/02_当前状态:8`、`memory/README:68`、`memory/05_历史明细:134/135`），因为**课程日历仍留在 README** —— 无差别全局替换 = 制造新错误。
- **历史不改写**：已发生的纪要与讲义里写的"README 机制4"保持原文，改由新文件开头一句声明"历史上的'README 机制4' = 本文"。
- **口径坑（工具）**：PowerShell `Get-Content` **默认按 GBK 解码**，UTF-8 中文文件的行数会被**少算**（183 行量成 135 行）→ 量行数用 `-Encoding UTF8`，或直接数字节里的 `0x0A`。教员差点用这个错数教学（自纠 ③）。
- **项目尺子两档（学员补充）**：练习项目 = 能用就行；**真要用的项目（pi agent / OSPP）= 走全套 `项目开发协议_v1.md`**；判据 = "这个项目你打算真的用吗？" → 已写进 `docs/教学机制与协作约定.md` 机制 4。
