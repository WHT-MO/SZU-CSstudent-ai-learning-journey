## 3. 第 1 题：P1980 计数问题 —— 两次 TLE 的诊断
| 版本 | 写法 | 结果 |
|---|---|---|
| A | 把 1..n 的所有数字字符**攒进一个列表**，再遍历数 | 小数据 AC / 大数据 **TLE**（n=10⁶ 时列表 ≈ **600 万元素**，且两趟遍历） |
| B | 一趟遍历 + 计数器（逐位 `int(b) == x`） | **本机 0.39s，洛谷仍 4 点 TLE** |
| C ✅ | 循环外 `x = str(x)`，逐位**字符比较** | 本机 **0.15s** → **洛谷 AC** |

- **实测对照（本机，`1000000 0`，结果均 488895）**：v1 0.39s｜v2 字符比较 **0.15s**｜v3 `''.join(...)+.count(...)` **0.09s**。
- **结论**：① `n ≤ 10⁶` 是提示 → "**能不存就不存**"，中间容器是 TLE 元凶；② **算法对 ≠ 一定过**，Python 层每次动作都贵，让 C 实现的 `.join()`/`.count()` 干活快一个数量级；③ 评测机比本机慢，**本地 0.39s 仍可能 TLE**。
- 教员自纠：曾推测"洛谷 Python 有时限放宽"——**未核实的推测，已当场撤回**。

## 4. 第 2 题：P1420 最长连号
| 版本 | 问题 | 结果 |
|---|---|---|
| A | `for b in range(n)` 里用 `a[b-1]` → **b=0 时 `a[-1]` 绕到末尾**，把"最后一个数+1==第一个数"当成"接着" | **洛谷 AC 属运气**；教员构造 `6 / 6 1 8 2 9 5`（真答案 1）实测输出 **2** → 露馅 |
| B | 想跳过第一轮却写了 **`break`** | **更糟**：第一轮就掐死整个循环，`n>1` 全部只输出 1（原样例 `1 2 3 5 6 7 8 10` 输出 1） |
| C ✅ | 改 **`continue`** | 六个用例全过（含 `6 1 8 2 9 5`=1、样例=4、n=1=1、整串连号=5） |

- **两个可带走的坑**：① **Python 负下标 `a[-1]` 合法、不报错** → "不报错的错"比报错难查；凡 `a[i-1]` 而 `i` 可能为 0 都要警惕；② **`break`（撤整圈） vs `continue`（跳本次）**——速查卡 §6 坑 4 教过、考过，今天原样撞上。
